@ui-kit.ai uses a **design token** based theming system to provide a consistent look and feel
across components. The theme is customizable, allowing you to adjust colors to match your brand
or personal preferences.

The theme is implemented in Tailwind using custom CSS variables. This enables powerful extra
functionality, like the **intent API**.

## Theme editor

The theme editor lives in the site nav — the palette button, on every page. Pick a preset or mix
your own seed colors, turn the style knobs, and the entire site re-themes as you type. Your
theme is kept in this browser until you reset it, and **Copy CSS** hands you a stylesheet that
overrides the one shipped in `@ui-kit.ai/components/style.css`.

<ButtonThemeEditor />

Generate the same CSS at build time with the `@ui-kit.ai/theme` API:

```ts title="generate-theme.ts"
import { themeCss } from '@ui-kit.ai/theme'

const css = themeCss({
  colors: {
    default: '#3E63DD',
    error: '#E54666',
    info: '#3E63DD',
    success: '#29A383',
    warning: '#FFC53D',
  },
  depth: 'some',
  radius: 'some',
  saturation: 'some',
})
```

## Depth

`depth` sets how far interactive surfaces lift off the page. It is optional, and
defaults to `some`.

| Depth  | Look                                                             |
| ------ | ---------------------------------------------------------------- |
| `none` | Flat: small elements drop their shadow. Overlays keep theirs.    |
| `some` | The default — a hairline shadow under buttons, fields and cards. |
| `lots` | Adds a lit top edge and a soft gradient to every accent fill.    |

## Radius

`radius` sets how far corners round, by the scale of the thing wearing them. Turning it up
pills the controls and leaves the surfaces around them in proportion. It is optional, and
defaults to `some`.

| Radius | Look                                                         |
| ------ | ------------------------------------------------------------ |
| `none` | Square: every step collapses to zero.                        |
| `some` | The default — Tailwind's own scale, from `xs` through `4xl`. |
| `lots` | Buttons and fields go pill; cards and dialogs round a shade. |

## Saturation

`saturation` sets how much of the seed color bleeds into the backgrounds, borders and body
text derived from it. Accent fills and tints keep the seed as mixed. It is optional, and
defaults to `some`.

| Saturation | Look                                                      |
| ---------- | --------------------------------------------------------- |
| `none`     | Near-grey surfaces, with a hint of the seed left in them. |
| `some`     | The default — surfaces carry a clear tint of the seed.    |
| `lots`     | Surfaces and body text lean hard into the seed's hue.     |

## Intent API

The intent API allows using color to communicate semantic meaning in the UI. All colors may be
overridden using the intent API, though it is recommended to use this feature sparingly to
preserve meaning.

Most components accept an `intent` prop, which swaps the `--theme-default-*` tokens for the
tokens of the given intent:

| Intent      | Usage                                                |
| ----------- | ---------------------------------------------------- |
| `undefined` | The default, neutral palette.                        |
| `info`      | Informational, non-blocking messaging.               |
| `success`   | Confirmation that an action succeeded.               |
| `warning`   | Something needs attention, but is not yet a failure. |
| `error`     | A failure, or a destructive action.                  |

## Background color

The available background colors are an intentionally limited set of colors focusing on the
following use cases:

- **Backgrounds**: Page backgrounds, and raised elements.
- **Tints**: Used primarily for communicating selection state within menus & lists.
- **Accent**: Used for emphasis, primarily on buttons and other interactive elements.

| Token                              | Utility            |
| ---------------------------------- | ------------------ |
| `--theme-default-bg-base`          | `bg-base`          |
| `--theme-default-bg-base-raised`   | `bg-base-raised`   |
| `--theme-default-bg-tint`          | `bg-tint`          |
| `--theme-default-bg-primary`       | `bg-primary`       |
| `--theme-default-bg-primary-hover` | `bg-primary-hover` |

## Text

The available text colors are also quite limited:

- **Accent**: Engineered to have a suitable contrast ratio against the accent background color.
- **Placeholder**: Suitable for placeholders in form fields.
- **Lo contrast**: Used for secondary text, such as descriptions and labels.
- **Hi contrast**: Used for primary text, such as headings and body text.

| Token                              | Utility            |
| ---------------------------------- | ------------------ |
| `--theme-default-text-hi-contrast` | `text-hi-contrast` |
| `--theme-default-text-lo-contrast` | `text-lo-contrast` |
| `--theme-default-text-placeholder` | `text-placeholder` |
| `--theme-default-text-accent`      | `text-accent`      |

## Border

The available border colors are also quite limited:

- **Default**: Used for subtle borders, such as in cards and panels.
- **Field**: Used for form field borders.
- **Field hover**: The hover state of a form field border.

| Token                                | Utility              |
| ------------------------------------ | -------------------- |
| `--theme-default-border-default`     | `border-default`     |
| `--theme-default-border-field`       | `border-field`       |
| `--theme-default-border-field-hover` | `border-field-hover` |

## Surfaces

The `bg-*`, `text-*` and `border-*` utilities each paint one property. An interactive accent
fill needs several of them at once, plus whatever the current `depth` adds, so it gets a single
utility instead:

`surface-primary` paints the accent fill, its gradient, `text-accent`, the letterpress and the
depth shadows, and moves through its hover and pressed states off React Aria's `data-hovered`
and `data-pressed` attributes.

`Button`, `Tag` and `Checkbox` are built on it, and it follows the intent API like every other
utility. Reach for the plain `bg-primary` when you want the color alone — a swatch, say — and
`surface-primary` when the element is something the user presses.
